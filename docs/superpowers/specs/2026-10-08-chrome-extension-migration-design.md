# Himawari Blog Automator: Chrome 확장 방식 전환 설계

작성일: 2026-10-08 (한국 시간)

## 목표와 비교 기준

사용자 요청은 새 저장소의 개선사항을 비교해 현재 프로젝트를 업데이트하는 것이며, 사용자는 **Chrome 확장 방식 전환까지 진행**을 선택했다.

- 현재 프로젝트: `mharuki78/blogauto-naver`, 커밋 `91982a28eeb5790af7a900d081a80980d6043b0c`, 앱 0.1.4.
- 비교 저장소: [boksajang/naverblog-extention](https://github.com/boksajang/naverblog-extention), 확인한 커밋 `1dd76f0`, 앱 0.2.5-rc.2, 확장 0.3.16.
- 성공 기준: 기존 계정·원고 생성·Himawari 기능을 이어 쓰면서, 데스크톱의 네이버·티스토리 로그인 확인과 글쓰기를 일반 Chrome의 확장으로 수행한다. 앱이 Chrome을 반복 새로고침하거나 로그인 중 종료하지 않는다.

## 비교 결과와 적용 범위

| --- | --- | --- |
| 일반 Chrome + Manifest V3 확장 | 현재 데스크톱은 Playwright 브라우저를 직접 제어 | Chrome 실행·확장·로컬 연결·발행 엔진 이식 |
| 계정별 연결 코드와 연결 상태 | 현재는 저장된 브라우저 프로필과 세션 상태 | 설치 폴더 준비, 계정별 Chrome 열기, 코드 연결, 상태·취소 UI |
| 작성 진행 상태·발행 결과 기록 | 현재 완성 원고 발행 재개는 있지만 확장 작업 기록은 없음 | 확장 작업 기록과 플랫폼별 완료 기록으로 중복 발행 방지 |
| 예약 목록·임시글 목록 확인 | 현재 URL·편집기 중심 완료 확인 | 새 엔진의 완료 증거와 기존 공개·비공개·예약 발행 옵션 연결 |
| 사용량 조회를 로컬 기록으로 처리 | 현재 기록이 없으면 별도 `codex exec` 호출 | 모델 호출 없이 사용량 표시 갱신 |
| 설정 파일 교체 방식으로 저장 | 현재 설정·계정 파일에 직접 덮어쓰기 | 쓰기 실패 시 이전 설정이 남도록 저장 개선 |
| 실제 CLI 모델 목록 조회 | 현재 캐시와 GPT-6.1 Sol 등을 포함한 목록 | 현재 모델 선택과 호환되는지 확인 후 별도 항목으로 관리 |
| 생성 단계 체크포인트·모델 변경 재시도 | 현재 상품 참고자료·실물 사진을 사용하는 생성 흐름과 구조가 다름 | 현재 생성 흐름을 보존하고, 이번에는 발행 재개에 필요한 부분만 적용 |
| 별도 윤문 단계, PDF/HWP/HWPX·OCR | 추가 모델 호출·문서 분석 의존성이 필요 | Chrome 전환의 필수 범위에 포함하지 않음 |

새 저장소의 설정 정규화는 자동 주제와 생성 후 발행을 강제한다. 그대로 복사하면 현재의 직접 주제 입력과 “생성만 하기” 동작이 바뀐다. 새 생성 프롬프트에는 Himawari 상품 정체성·정보 중심 본문·짧은 상품 안내 검증이 없어 현재 생성기를 유지한다.

## 선택한 접근

### 권장: 현재 앱에 새 데스크톱 발행 엔진을 연결

기존 `src/lib/naverPublisher.js`와 `tistoryPublisher.js`는 웹앱 및 기존 Playwright 검사에서 계속 사용한다. 데스크톱 `main.js`는 별도 확장 발행 어댑터를 사용하도록 전환한다. 확장 미연결 시 자동으로 다른 엔진에서 발행하지 않고 연결 안내를 제공한다.

전체 소스를 새 저장소로 교체하는 접근은 작은 코드베이스를 얻지만 현재 상품·사진·모델·웹앱 기능을 다시 구현해야 한다. 기존 방식에 소규모 수정만 적용하는 접근은 간단하지만 사용자가 선택한 Chrome 확장 전환을 충족하지 못한다.

### 유지할 사용자 기능

- Himawari 로고, 앱 이름·아이콘, 기존 화면 구성.
- 계정·카테고리·키워드, 직접/자동 주제, 생성만 하기, 반복 작업.
- GPT-6.1 Sol 선택과 ChatGPT/Codex 연결.
- 상품 URL·모델·근거, 여러 참조 사진, 제목/본문 이미지, 기존 사실·상품 검수.
- 기존 Next/Vercel 웹앱과 클라우드 발행 경로.
- 실행 파일 옆 `runtime`의 설정·계정·작업 이력·이미지.

## 구성과 데이터 흐름

1. **Chrome 실행기**: 계정 ID에서 결정한 `runtime/account-chrome/` 폴더로 일반 Chrome을 연다. 현재 Playwright 프로필의 쿠키를 복사하지 않는다. 계정 목록은 그대로 사용하되 새 창에서 사용자가 처음 한 번 로그인한다.
2. **확장 설치 준비**: 배포에 포함한 확장을 사용자 데이터 폴더의 안정된 설치 경로에 복사한다. 앱에서 경로 복사와 `chrome://extensions` 설치 안내를 제공한다. Chrome 개발자 모드에서 압축해제된 확장을 등록하는 절차는 계정별로 필요하다.
3. **로컬 연결 브리지**: `127.0.0.1:46321`에서만 통신한다. 일회성 연결 코드와 계정별 토큰, 확장 출처·요청 크기 제한을 사용한다. 토큰은 UI·로그에 노출하지 않는다. 단일 앱 인스턴스로 포트·작업 중복을 막는다.
4. **데스크톱 발행 어댑터**: 현재 제목·본문·이미지·태그·카테고리·공개/예약 옵션을 확장 작업으로 전달한다. 기존 사진 중 실제 참고 원본과 생성 이미지는 AI 활용 표시에서 구분한다.
5. **Chrome 확장**: 네이버 글쓰기 프레임을 찾고 입력 상태를 검증한다. 원본 확장의 주소 검사에도 `?Redirect=Write` 누락이 있으므로, 현재 0.1.4가 지원하는 직접 글쓰기·PostWriteForm·Write redirect의 같은 블로그 판정을 이식한다. 이미 열려 있는 Write 프레임을 홈 화면으로 오인해 다시 이동하지 않는다. 네이버·티스토리의 로그인 또는 보안 확인이 필요하면 기다리고, 사용자가 완료하면 같은 작업을 이어간다. Chrome은 앱 종료나 세션 확인 실패로 닫지 않는다.
6. **완료·재개 기록**: 각 플랫폼의 발행 시도 전과 결과 후 원고와 상태를 저장한다. 완료한 플랫폼은 재시도에서 건너뛴다. 최종 발행 이후 연결이 끊겨 결과가 불확실하면 자동 재발행하지 않고 원고와 불확실 상태를 유지한다. 예약 발행은 예약 목록과 시각으로 확인한다.

## 화면과 오류 처리

- 계정 카드: 기존 세션 확인에 더해 **Chrome 열기**, **확장 연결 코드**, **연결 해제/대기 취소**를 제공한다.
- 공통 설정 영역: **확장 설치 폴더 준비** 및 설치 안내. 티스토리 사용 시 공용 Chrome과 연결 코드를 제공한다.
- 확장 연결 여부와 로그인 여부를 구분한다. 저장된 과거 “세션 정상”만으로 새 연결이 정상이라고 표시하지 않는다.
- 글 생성 전 실제 연결·편집기 준비를 확인한다. 연결되지 않았거나 확장이 구버전이면 모델 실행 전 안내한다.
- 앱 종료 시 브리지는 중지하지만 일반 Chrome과 작성 내용은 유지한다. 재실행 때 진행 중이던 최종 발행은 불확실 상태로 복구한다.
- 업데이트 중 기존 보류 원고는 이전 완료 증거가 없는 플랫폼을 자동 완료로 처리하지 않는다. 확인되지 않은 발행을 되풀이하지 않도록 별도 상태로 보존한다.

## 저장·패키징

- 기존 `runtime` 경로와 JSON 스키마를 유지하고 새 연결/발행 기록만 추가한다.
- 설정·계정 저장은 동일 폴더의 임시 파일 작성 후 교체한다. 실패하면 이전 파일을 보존하고 오류를 전달한다.
- 확장 코드·정적 리소스를 EXE에 포함하고, 로그인·프로필·연결 토큰·작업 기록은 배포하지 않는다.
- 현재 Electron/Node 의존성에서 지원되는 API를 확인한다. 문서/OCR 목적의 새 의존성이나 Electron 대규모 업그레이드는 이번 전환에 필요하지 않다.
- 사용자용 설치 안내와 업데이트 내역에 최초 확장 설치·재로그인 절차를 추가한다.

## 검증과 완료 기준

- 로컬 HTTP 브리지: 연결 코드, 계정 분리, 작업 취소·재시작, 인증·출처·이미지 경로 제한, 중복/불확실 발행 방지.
- 실제 Chrome의 가짜 네이버·티스토리 페이지: 로그인 대기, `?Redirect=Write` iframe 재사용과 다른 블로그 거부, 제목·본문·이미지·카테고리·태그, 직접/예약/임시저장 완료 판정. 검증 때문에 실제 계정에 글을 게시하지 않는다.
- Electron 화면: 기존 Himawari·상품·사진·모델 기능과 새 연결·설치 UI가 함께 작동하는지 확인.
- 사용량 표시: 로컬 기록이 없을 때 모델 프로세스를 실행하지 않는지 확인.
- 설정·계정 저장: 교체 실패 후 이전 파일이 유효한지 확인.
- 전체 `npm run check`, 필요한 Electron UI 검사, Windows EXE 빌드 및 패키지 코드/리소스 확인.
- 실제 문제 PC에서의 네이버·티스토리 로그인·발행 결과는 로컬 모의 검사와 구분하여 보고한다.

## 설계 검토 상태

사용자는 Chrome 확장 전환 범위를 선택했고, 이 문서에 대한 확인 요청에 **설계대로 진행**이라고 답했다. 승인된 설계에 따라 구현 계획을 작성한다.
